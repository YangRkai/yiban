# 弈伴 · YiBan

Windows 上的围棋工具，提供纯本地 PVE 和视频联动两种模式。默认进入 PVE：玩家直接在棋盘落子，KataGo 自动应手，无需 OBS 或外部围棋客户端。

> 当前为实验性版本。图像识别、自动定位和连续自动落子仍有使用限制。自动化测试通过不代表已经完成真实客户端的完整对局验证。

## 功能

- 纯本地 PVE：自动应手、电脑先手、整回合悔棋。
- 视频联动：同一窗口查看视频预览和本地 AI 棋盘。
- 支持 9、13、19 路棋盘，AI 执黑或执白。
- 使用 KataGo GTP 接口，可配置 CUDA 或其他受支持后端。
- OBS 视频设备选择、自动网格定位及手动四角定位。
- 读取已有黑白子，处理上一手三角标记；提供可编辑的局面核对窗口。
- 自动同步、手动补子恢复、重新读盘并继续。
- 开始自动、停止自动、F8 停止、新开本地一局、悔棋和 SGF 保存。
- 可选择只读盘计算，或向指定窗口发送点击并检查是否落子。

## 环境

- Windows；当前桌面点击实现依赖 Win32。
- Python 3.11 或更高版本，安装时包含 Tcl/Tk。当前开发测试使用 Python 3.13。
- 自行安装 KataGo，并下载与其兼容的模型。
- 使用视频输入时需安装 OBS Studio，设置棋盘捕获场景并启动虚拟摄像机。
- GPU 后端依赖由所选 KataGo 构建决定，不随本仓库提供。

## 安装与启动

在仓库根目录运行 PowerShell：

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item board/runtime.example.json board/runtime.json
```

修改 `board/runtime.json` 中的可执行文件、模型、GTP 配置和 DLL 目录，填写本机绝对路径。配置所指文件必须存在。引擎工作目录使用配置中的可执行文件所在目录。

```powershell
.\.venv\Scripts\python.exe board/app.py
```

此源码发行版不包含开发机专用启动脚本。

## 不使用显卡：CPU 推理

可使用 CPU 版 KataGo。准备其可执行文件、兼容模型和 CPU GTP 配置后，在“设置 → 配置 CPU 引擎”选择三个文件，再切换“推理设备”为 CPU。

也可将 `board/runtime.cpu.example.json` 复制为 `board/runtime.cpu.json` 并修改路径。只有 CPU 配置、没有 GPU 配置时，程序默认启动 CPU。后续选择保存在本机 `compute-settings.json`。

不会把 GPU 引擎仅改名当作 CPU 引擎。请自行安装真实 CPU 构建及其运行依赖。CPU 通常更慢，可用轻量或休闲搜索预算。后端切换保留盘面和轮次，重新建立起始局面，原有历史不迁移。

当前开发机尚未执行真实 CPU 版引擎验收；GPU 集成测试不代表 CPU 推理已通过。

## 纯本地 PVE（默认）

- 在“设置”里选择“本地 PVE”，选择棋盘路数和思考时间。
- 底部设置 AI 执子颜色，玩家执相反颜色；电脑执黑时新局自动先下。
- 单击棋盘落子，电脑自动应手；思考中不接受玩家重复落子。
- “悔棋”在电脑已应手后退回一整个回合；“新开一局”清空本地局面。
- “停止”或 F8 暂停，“继续对弈”恢复。
- 顶部可选轻量、休闲、标准、强力四档。等级控制搜索上限，不代表真实段位，低档仍可能很强。
- 切换模式会停止旧模式的自动任务；视频配置保留。PVE 不自动打开视频设备或发送外部窗口点击。

## 视频联动流程

1. 在 OBS 中显示完整棋盘，启动虚拟摄像机。
2. 打开弈伴，在“设置”中选择视频源、路数与目标窗口。自动定位失败时可手动选四角。
3. 设置 AI 颜色；程序优先依据所选野狐窗口手数判断轮次，其次使用唯一的上一手三角标记。没有可靠提示时可手动设置轮次。
4. 点击“开始自动”。稳定画面会自动接入。只需要建议时，在设置中选择“只读盘并计算”。
5. 顶部查看状态。F8 或“停止”关闭自动读盘与点击。已经发出的鼠标事件无法撤回。
6. 本地局面误操作时，选择恢复轮次并点击“重新读盘并继续”。这不会撤销外部客户端已经落下的棋子。

“新开一局”重置本地引擎，并备份上一局；不会替你在外部客户端创建或加入对局。已有自动运行状态可等待新局空盘后继续。

## 已知限制

- 自动定位针对基本正视、完整、等距的屏幕棋盘；透视拍摄、多棋盘同屏、遮挡及窗口布局变化可能失败。
- 颜色、缩放、主题、悬停标记、动画和裁切会影响识别；边缘支持已有测试，但不能保证任意裁切都可读取。
- 从单帧导入不会恢复完整落子历史、历史劫争、连续停一手记录。导入后的悔棋仅覆盖导入后的手数。
- 自动点击依赖目标窗口可激活、未遮挡、尺寸一致及点击前局面核验。换房间或目标变化可能需要重新定位。
- 标题手数是否计入停一手取决于客户端行为，尚未完成现场验证；终局确认等交互尚不完善；AI 停一手或认输需要在客户端手动处理。
- 实际野狐客户端的连续自动对局尚未完成系统性的端到端验收。
- 当前存在线程及界面生命周期的历史问题；遇到异常应提交完整复现，不应仅根据某次测试通过推断不存在问题。

## 本地数据

`board/runtime.json` 保存本机引擎路径；`camera-settings.json` 保存设备及定位设置；`game-backups/` 保存新局前的局面快照；`import-position.sgf` 是导入临时文件；`engine.log` 是引擎日志。这些文件不应提交到公开仓库。

## 开发与测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s board -p 'test_*.py'
```

完整测试依赖 Windows、Tcl/Tk、本机 KataGo 配置和模型。部分测试使用真实引擎，部分使用图像素材或模拟对象；模拟点击测试不会证明实际客户端能够接受点击。

原始截图素材不分发，对应测试显式跳过；未配置 runtime.json 时真实引擎和界面集成测试显式跳过。

## 使用范围与第三方项目

本项目用于本地练习、复盘，以及参与者知情同意且平台允许的 AI 对局。使用前应自行确认目标平台规则；不应把 AI 辅助伪装成人类独立对弈。

本项目不隶属于 KataGo、OBS Studio 或任何围棋客户端。第三方程序、模型、GPU 运行库不随源码发布，各自权利和许可独立。
