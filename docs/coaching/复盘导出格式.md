# 教学版复盘包约定（待实现）

此文件定义下一版导出器的数据约定；当前 v0.2.2 尚没有自动教学导出按钮。

## 用户流程

对局自动保存在本机。用户选择“提交给 AI”，选择最近若干局或指定对局，预览数量和隐私范围，导出 ZIP。同时提供可直接上传的 Markdown 汇总和“复制提示词”。不自动联网或代用户发送。

ZIP 包含 AI复盘提示词.md、manifest.json、review.md、games/<game_id>.sgf、analysis.json。AI 不支持 ZIP 时，用户可上传 review.md 和相关 SGF；汇总过大时按局拆分，保留相同证据编号。没有分析结果也允许导出，但清楚标注未分析。

默认不导出账号、绝对路径、设备名称、摄像头画面或桌面截图。玩家用本机随机 player_id 区分；多人共用电脑需选择玩家或访客，不能把多人棋谱混成一个人的习惯。用户可以删除记录。

## manifest.json

- schema_version：初始为 1.0；export_id、exported_at。
- player_id：匿名本机标识；范围内的 game_id 列表。
- coverage：实际记录局数、已分析局数、已分析玩家手数、失败/跳过手数及原因。
- games：每局包含 game_id、文件名、开始/结束时间、状态（进行中/完成/中断）、玩家执子、棋盘大小、规则、贴目、让子、初始局面、难度、对手类型。
- content_hash：用于检测相同棋谱重复导出。不能用导出次数增加样本数。

## 自动落子记录

每次合法落子成功后写入，再进行耗时分析。采用临时文件加原子替换，避免中断破坏完整记录。非法尝试不进入实际棋谱。悔棋保留事件与原分支，活动主线只包含当前局面；统计默认不计撤回分支。新开一局生成新 game_id。提子、停一手、认输、切换执子、初始摆子和终局状态需显式保存。用户中途修改规则或导入局面时记录新的片段边界。

## analysis.json

每条玩家落子证据包含：

- evidence_id、game_id、move_number、episode_id、player_color、actual_move。
- position_hash_before：棋盘、轮次、规则、贴目和完整历史上下文的标识；分析必须从完整历史重放，不能仅靠棋子集合恢复打劫状态。
- status：unanalysed / analysing / complete / failed / unstable；失败原因。
- engine_version、model_hash、规则/贴目、分析时间、visits、time_limit、score_perspective。
- recommended_move、candidate_moves（各含坐标、搜索量、玩家视角估计分数、PV）。
- actual_move_analysis：对实际下法的独立评估；候选列表未包含实际下法时，不能凭空计算损失。
- loss_points：可比评估下推荐与实战下法的分差；无法比较时为 null。不得把 null 当作 0。
- verification：更高预算复核是否完成、复核损失、推荐点及是否一致；未复核不得冒称可靠。
- observations：每个标签含依据、检测方式及 evidence_id；没有可靠检测器的棋理标签不自动生成。

坐标统一 GTP：A1 在左下，跳过 I；棋盘大小随局携带。PV 明确首手颜色，pass/resign 使用字符串。SGF 使用标准坐标，导出器负责转换。

## 教学可靠性

陪练可以放弱，但复盘必须用独立、明确记录的分析预算，不继承放弱参数。优先复核疑似关键失误；分析取消、失败或低预算不阻止继续下棋。有限搜索不能保证棋理结论绝对正确，界面显示估计和复核状态。

讲解至少展示原局面、实战变化和建议变化，可逐步演示并退回，不修改真实对局。没有可验证的棋理原因时显示“建议变化更优，具体原因待核实”，不能由自然语言模型自行补齐。

验收包括：断电式写入中断、悔棋/新局、黑白换边、重复导出、未分析与失败样本、提子/劫/停着、分数视角、实际下法不在候选中、样本不足不声称习惯，以及仅使用随包 CPU 引擎的离线流程。
